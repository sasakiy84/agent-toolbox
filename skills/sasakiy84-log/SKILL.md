# Sasakiy log
人間が理解できるように作業ログを書くときのルール。
プロジェクトの設定で人間用の成果共有ディレクトリが指定されている場合は、そこにログを出力する。
ファイル名、ファイルパスの指定がない場合は、`LOG.md` という名前にする。

## フォーマット
```md
# YYYY-MM-DD HH:MM:SS <タイトル>
<本文>
```

## ルール
- 日付はログを書いた時刻で、コマンドで日本時間で取得する（例: `TZ="Asia/Tokyo" date '+%Y-%m-%d %H:%M:%S'`）
- ログは 1 つの作業単位ごとに書く。作業単位は何らかの意思決定を伴う作業のまとまりで、1 つのコミットに相当する。作業単位が複数ある場合は、複数のログを作る。
- 日本語で書く
- 最新のログが上に来るようにする


## 内容
- やったこと、結果の要約、意思決定の理由をメインに書く
- やってきたことの概要を把握できればいいので、それぞれのログが原則 2-10 行程度になるようにする

## 例

```md
# 2024-06-01 11:12:24 メモ閲覧機能のテストコードの追加
メモ閲覧機能のテストコードを追加した。メモの検索機能が正しく動作することを確認するために、タイトルと本文に対して部分一致検索を行うテストを追加した。
DB も含めた結合テストはコードが複雑になるため、メモの検索機能のロジックを切り出して、DB を使わない単体テストを追加した。

# 2024-06-01 11:04:20 レビューの実行
workflow skill にしたがってレビューした結果、以下の指摘を受けた。

- メモの検索機能がタイトルと本文に対して部分一致検索を行う仕様になっているが、転置インデックスでの検索もしたほうがよい
- テストコードがないので、テストコードを追加する必要がある

ユーザーからの要望は「簡易的なメモ閲覧機能」なので、転置インデックスでの検索は不要と判断した。
テストコードは、メモの検索機能が正しく動作することを確認するために追加する。

# 2024-06-01 10:56:03 メモ閲覧機能の実装
ユーザーからの要望があったので、メモ閲覧機能を実装した。
詳細な指定がなかったため、一般的な閲覧機能として、メモの一覧表示、詳細表示、検索機能を実装した。
検索は、メモのタイトルと本文に対して部分一致検索を行う。作成日時では表示しない。
```
