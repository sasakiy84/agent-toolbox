# Sasakiy Explain

指定された技術的な対象について、分かりやすく説明する。対象はコード変更、diff、branch、PR ドキュメント、仕様、設計、実装、運用手順、実験結果など。

## Sections

- Summary: 前提、重要な結果を3文程度でまとめる。表のほうがわかりやすいときは表を挿入する。重要な未定義語は、文で、または修飾語で説明する。修飾語で説明するとは、「〜〜〜としてのXXXX」のような形式。
- Intuition: 対象の核となる直感を説明する。細部ではなく本質に集中する。具体的な小さなデータ例を使い、図や表を多めに使う。重要な未定義語は、文で、または修飾語で説明する
- Background: 対象に関係する既存の仕組みや背景を説明する。読者がどこまで知っているかは分からないため、説明のために絶対に必要な広めの背景と、対象に直接関係する狭い背景の両方を含める。
- Details: 対象の内容を高いレベルで順に説明する。コード変更なら変更内容を、ドキュメントなら構成や主張を、仕様や設計なら責務や判断を、理解しやすいまとまりに分けて並べる。検証に使ったコードやコマンドを末尾に記載する

Background と Details は、ファイルに書くとき、あるいはそれらを含めるように指示があったときのみ、説明に含める。
ユーザーの理解のノイズにならないように、新しい概念や用語、変数名などを導入するときは、それが本当に説明に必要なものか、説明のときはもっと単純化できないかを検討する。本当に必要だったときは、初出箇所で最低限の説明がなされているかを確認する。

## Format

- 出力はチャット。ただし、ユーザーから指示があったときは 1 つの自己完結した Markdown ファイルにする。
  - ファイルの置き場所は、ユーザーの指示、既存プロジェクトの同じようなファイルが入っている場所、gitignore されている場所でドキュメントをおけそうな場所、グローバルな tmp 領域の順番の優先度
  - ファイル名は、日付順に並べやすいように必ず今日の日付から始める。
    - 形式: `YYYY-MM-DD-<slug>.md`
    - 例: `2026-01-12-<slug>.md`
- 1 つの長いページとして読めるように、見出しと目次を付ける。
- 日本語で書く。
- 接続語や導入文などを使い、セクション間のつながりが滑らかになるようにする。
- ASCII アートは使わない。
- 図は Mermaid、Markdown の表で表現する。
- 具体的な例のデータを含める。
- 指標が多ければいいというわけではない。できるだけ重要な指標に絞る。質的に同じ指標はできるだけ採用しない
- 説明が短ければいいというわけではない。複雑な箇所は具体例を出しながら丁寧に説明する
